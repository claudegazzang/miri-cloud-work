## 0. 조사 방법과 신뢰도 안내

- **라이브러리 정보**(버전, 라이선스, 최근 배포일)는 npm·PyPI 레지스트리 API와 GitHub 저장소 페이지에서 **직접 확인**했습니다. lunar-javascript는 패키지(1.7.7)를 내려받아 소스 코드에서 메서드 이름과 절기 시각의 기준 시간대를 확인했습니다.
- **법령**은 국가법령정보센터 OpenAPI 데이터를 Git으로 관리하는 `legalize-kr` 저장소의 조문 원문을 직접 읽고 인용했습니다(각 법령의 공포일·시행일을 함께 적음).
- **한국 표준시·서머타임 이력**은 IANA tz 데이터베이스 원본(`asia` 파일)을 직접 읽었습니다.
- **공공데이터포털(data.go.kr), 앱스토어, 언론 기사**는 이 환경에서 직접 열 수 없어 **검색 결과(제목·URL·발췌 요약)**에 의존했습니다. 이런 항목은 "(검색 결과 기준)"으로 표시했습니다.
- **경쟁사 가격대는 확인하지 못했습니다.** 검색 한도가 소진되었고 앱스토어 페이지에 접속할 수 없었습니다. 가격표는 (미확인)으로 비워 두고 조사 방법만 적었습니다.
- 아키텍처·전략·로드맵은 조사자의 **제안**이며 사실 주장이 아닙니다.
- 이 문서는 법률 자문이 아닙니다. 오픈 전에 전문가 검토를 받으세요.

### 1-2. 입력 화면에서 꼭 다룰 엣지 케이스

1. **음력 윤달** 여부 체크박스(윤달이 있는 해에만 노출).
2. **출생 시각 모름**: 시주를 빼고 3주(6자)로 풀이하고, 결과 화면에 그 사실을 표시합니다.
3. **자시(子時) 처리 방식**: 야자시/조자시(23시~24시 출생을 당일로 볼지 다음 날로 볼지) 옵션. 국내 대표 무료 만세력 앱인 원광만세력에도 "야자시 적용 명조에서 일주가 다르게 나온다"는 리뷰 불만이 있습니다[^29]. 기본값과 변경 옵션을 화면에 명시하세요.
4. **출생지 경도 보정(진태양시)** 적용 여부: 기본값 정책을 정하고 결과 화면에 "보정 전 시각 → 보정 후 시각"을 보여 줍니다(3장).
5. **서머타임 기간 출생자**(1948~1951, 1955~1960, 1987~1988)와 **표준시가 UTC+8:30이던 기간 출생자**(1908~1911, 1954~1961): 자동 보정하고 안내 문구를 띄웁니다(3장).
6. **해외 출생자**: 출생지 시간대(IANA tz)와 경도를 입력받습니다.

### 2-2. 선택 권고 (제안)

- **계산 엔진(사주 4주·대운)**: 6tail 계열(`lunar-javascript`/`lunar-python` 또는 후속작 `tyme4ts`)은 기능이 가장 풍부하고 사용자가 많습니다. 다만 **중국 기준 시간(UTC+8)으로 절기를 계산**하므로(2-3절), 한국 시간대 보정 계층을 직접 덧씌워야 합니다.
- **한국 음력 날짜 표시**: `korean-lunar-calendar`(KASI 기준)를 쓰거나, 아래 KASI API로 만든 표와 교차 검증하세요.
- **한국 특화 패키지**(`manseryeok` 등)는 서머타임·표준시 이력을 이미 처리하지만 스타 수와 사용자가 적습니다. **채택하려면 4장의 회귀 테스트를 통과하는지 먼저 확인하세요.**
- 엔진 하나에 묶이지 않도록 `CalendarEngine` 인터페이스를 두고 구현체를 바꿀 수 있게 설계하세요(6장).

### 2-3. 확인된 기술적 사실: lunar-javascript 절기 시각은 UTC+8 기준

- lunar-javascript 1.7.7 소스의 절기 계산 함수는 역표시(ΔT)를 뺀 뒤 `ONE_THIRD`(= 1/3일 = 8시간)를 더합니다. **절기·합삭 시각이 베이징 시간(UTC+8) 기준**이라는 뜻입니다[^12]. README에도 시간대 처리 설명은 없습니다[^1].
- 따라서 한국 시각(UTC+9)으로 표시하려면 **+1시간**을 해야 합니다. 서머타임이나 UTC+8:30 시기 출생자는 별도로 처리해야 합니다.
- 같은 이유로 합삭이 자정 근처에 있는 달은 **중국 음력과 한국 음력의 날짜가 하루 어긋날 수 있습니다**(추론). 한국 음력 날짜는 KASI 기준 데이터로 검증하세요.
- sxtwl도 같은 寿星 알고리즘 계열이므로 기준 시간대를 반드시 확인하세요(미확인).

### 2-4. lunar-javascript 사용 예 (메서드 이름은 소스에서 확인, 실행 검증은 하지 않음)

```js
// npm i lunar-javascript   (1.7.7, MIT)
const { Solar } = require('lunar-javascript');

// 주의: 이 라이브러리는 입력 시각을 '절기 기준 시간대(UTC+8)'와 같은 벽시계로 취급한다.
// → 한국 출생 시각을 그대로 넣으면 절기 경계 비교가 1시간 어긋난다(2-3절).
const solar = Solar.fromYmdHms(1990, 5, 15, 14, 30, 0);
const ec = solar.getLunar().getEightChar();
ec.setSect(2);              // 자시 처리 방식(1 또는 2) - 소스상 기본값 2
console.log(ec.getYear(), ec.getMonth(), ec.getDay(), ec.getTime()); // 년주·월주·일주·시주
const yun = ec.getYun(1);   // 1=남, 0=여 (대운)
console.log(yun.getDaYun().map(d => `${d.getGanZhi()}(${d.getStartAge()}세)`));
```

## 3. 시간 보정: 표준시·서머타임·진태양시

### 3-1. 한국 표준시와 서머타임 이력 (IANA tz `Asia/Seoul`, 원문 확인)

| 기간 | UTC 오프셋 | 비고 |
|---|---|---|
| ~1908-04-01 | +8:27:52 (LMT, 서울 지방평균시) | |
| 1908-04-01 ~ 1912-01-01 | **+8:30** | 대한제국 표준시(동경 127.5°) |
| 1912-01-01 ~ 1954-03-21 | +9:00 | 1945-09-08까지는 JST로 표기 |
| 1954-03-21 ~ 1961-08-10 | **+8:30** | 동경 127.5°로 환원 |
| 1961-08-10 ~ 현재 | +9:00 | 동경 135° |

서머타임(+1시간) 규칙(tz `Rule ROK`)[^15]:

| 연도 | 시작 | 종료 |
|---|---|---|
| 1948 | 6/1 00:00 | 9/12 24:00 |
| 1949 | 4/3 00:00 | 9월 7일 이후 첫 토요일 24:00 |
| 1950 | 4/1 00:00 | 〃 |
| 1951 | 5/6 00:00 | 〃 |
| 1955 | 5/5 00:00 | 9/8 24:00 |
| 1956 | 5/20 00:00 | 9/29 24:00 |
| 1957~1960 | 5월 1일 이후 첫 일요일 00:00 | 9월 17일 이후 첫 토요일 24:00 |
| 1987~1988 | 5월 8일 이후 첫 일요일 02:00 | 10월 8일 이후 첫 일요일 03:00 |

- **주의 1**: tz 메일링 리스트에서는 1948~1951년 규칙이 Zone 정의에서 빠져 있던 버그가 보고되었고(2019), 1954~1961년 기록은 한국어 위키백과와 옛 신문에 근거해 고쳤다는 논의(2014)가 있습니다[^16]. **사용하는 tz 데이터 버전에 따라 결과가 다를 수 있으니** 이 기간은 회귀 테스트에 꼭 넣으세요.
- **주의 2**: 연도별 정확한 시작·종료일은 자료마다 차이가 있습니다(예: 1948~1960년 또는 1961년, 6·25 전쟁 기간 중단 여부)[^17]. 중요한 고객 명식은 국가기록원·관보 원문으로 확인하는 절차를 두세요.
- 현행 법: 「표준시에 관한 법률」은 "표준시는 동경 135도의 자오선을 표준자오선으로 하여 정한다"고 하고, 대통령령으로 일광절약시간제를 할 수 있다고 정합니다(2011-05-19 시행)[^18].
- 한국천문연구원 자료에 따르면 한반도 중앙 경도는 약 127.5°이므로, 태양은 정오가 아니라 **대략 12시 30분 무렵 남중**합니다(검색 결과 기준)[^19].

### 3-2. 보정 알고리즘 (제안)

```
입력: 출생 '벽시계' 시각 T_local, 출생지 tz(예: Asia/Seoul), 경도 λ
1) T_utc = tz 이력(서머타임·+8:30 포함)으로 T_local을 UTC로 바꾼다.
2) 연주·월주 = T_utc를 'UTC로 저장한 절기 시각표'(입춘, 각 절입)와 비교해 정한다.
     → 엔진이 UTC+8 기준이면 표를 UTC로 바꿔 쓰거나, T_utc+8h를 엔진에 넣어 경계를 비교한다.
3) 시주용 시각:
     - 정책 A(표준시 그대로): T_local에서 서머타임만 뺀 시각
     - 정책 B(지방평균시): T_utc + λ × 4분
     - 정책 C(진태양시): 정책 B + 균시차(EoT, 연중 약 -14분 ~ +16분)
4) 일주 경계(자시) = 시주용 시각 기준 23:00 또는 00:00 (야자시/조자시 옵션)
5) 결과와 함께 '적용한 정책·보정량(분)'을 저장하고 화면에 보여 준다.
```

- 예: 서울(경도 약 126.98°)은 135°보다 약 8° 서쪽이라 지방평균시가 약 32분 늦습니다(계산값). urstory/manseryeok-js README도 서울 14:30을 13:58로 보정하는 예를 들고, 부산 약 -24분, 강릉 약 -28분을 제시합니다[^10].
- 보정 정책은 학파마다 다릅니다. **기본값을 하나 정하고, 사용자에게 바꿀 수 있는 옵션을 주고, 리포트에 정책을 기록**하는 것이 분쟁(환불) 예방에도 좋습니다.

## 5. 해석 텍스트 생성 전략

### 5-1. 규칙 기반 템플릿 vs LLM

| 항목 | 규칙 기반 템플릿 | LLM 생성(예: Claude API) | 하이브리드(권장) |
|---|---|---|---|
| 일관성·재현성 | 완전 결정론적 | 같은 입력에도 출력이 달라짐 | 계산과 '판단 근거'는 규칙, 문장은 LLM |
| 품질 | 문장이 기계적이고 반복됨 | 자연스럽고 개인화됨 | 자연스럽고 근거가 분명함 |
| 비용 | 거의 0 | 토큰 비용 발생 | 생성 결과를 캐시해 비용 통제 |
| 위험 | 낮음 | 환각(없는 신살 언급), 단정·공포 표현 | 근거 JSON 밖의 내용은 금지 |
| 초기 구축 | 문장 DB 작성 부담(60일주 × 항목) | 프롬프트 설계 | 둘 다 필요하지만 단계적으로 가능 |

### 5-2. 하이브리드 파이프라인 (제안)

```
[명식 계산] → [규칙 엔진: 근거 JSON 생성]
                 예) {일간:"갑목", 강약:"신강", 용신후보:["화","토"],
                      십신분포:{...}, 합충:[...], 대운:[...], 근거규칙ID:[...]}
            → [템플릿 문장(무료 요약)]          ← 결정론적, 즉시 응답
            → [LLM 문장화(유료 리포트)]          ← 근거 JSON만 입력, 구조화 출력
            → [검증기: 금칙어·단정 표현·근거 밖 용어 검사]
            → [저장: cache_key로 영구 저장]
```

- **LLM에는 근거 JSON만 주고 "이 안에 없는 사실(신살·합충)은 언급하지 말라"고 지시**합니다. 출력은 섹션별 JSON(제목, 본문, 근거규칙ID 목록)으로 받아 검증합니다.
- Claude API에서는 구조화 출력(`output_config.format`)으로 JSON 스키마를 강제할 수 있습니다[^20].
- **재현성**: Claude API는 최신 API 버전(2026-10-21)부터 `temperature` 같은 샘플링 파라미터를 보내면 400 오류를 돌려줍니다[^20]. **'temperature 0으로 재현'하는 방식은 쓸 수 없습니다.** 따라서 재현성은 **결과를 저장해서** 확보합니다.
  - `cache_key = hash(엔진버전, 보정정책, 명식정규화JSON, 규칙버전, 프롬프트버전, 모델ID, 섹션)`
  - 같은 키로 요청이 오면 저장본을 돌려줍니다. 버전이 바뀔 때만 다시 생성합니다. 유료 리포트는 **구매 시점의 스냅샷**을 고객에게 영구 제공합니다(환불 분쟁 대비).
- **비용 절감**:
  - 해석 규칙집·문체 가이드 같은 긴 고정 시스템 프롬프트는 프롬프트 캐싱을 씁니다[^20].
  - 띠별·일진 운세처럼 **미리 만들어 둘 수 있는 콘텐츠는 Message Batches API**로 처리합니다(비동기, 비용 50%)[^20].
- **모델·가격**(Anthropic 1st-party API 기준, 2026-10-06 캐시 정보이므로 사용 전 공식 가격 페이지에서 다시 확인)[^20]:

| 모델 | 모델 ID | 입력 $/1M 토큰 | 출력 $/1M 토큰 | 용도 제안 |
|---|---|---|---|---|
| Claude Opus 5.5 | `claude-opus-5-5` | $4.00 | $20.00 | 고가 프리미엄 리포트, 품질 평가자(LLM judge) |
| Claude Sonnet 5.5 | `claude-sonnet-5-5` | $2.00 | $10.00 | 일반 유료 리포트 |
| Claude Haiku 5.5 | `claude-haiku-5-5` | $0.10 (프롬프트 100K 이하) | $0.50 | 오늘의 운세·띠별 대량 생성 |

- **품질 관리(제안)**:
  1. 문체 가이드: 단정 금지("반드시 ~한다" → "~하는 경향이 있다"), 의료·법률·투자 조언 금지, 공포 조장 금지.
  2. 금칙어 필터: 사망·질병 단정, 특정 날짜 사고 예언 등.
  3. 평가 세트: 대표 명식 50~100개에 대한 기준 해설을 만들고, 프롬프트·모델을 바꿀 때마다 회귀 평가(LLM judge + 사람 표본 검수)를 돌립니다.
  4. 버전 관리: 프롬프트와 규칙을 Git으로 관리하고 리포트에 버전을 표기합니다.
- **개인정보 최소화**: LLM에는 이름·생년월일을 보내지 말고 **간지·근거 JSON만** 보내세요. 해외 LLM API로 개인정보를 보내면 「개인정보 보호법」 제28조의8(국외 이전)이 문제될 수 있습니다(7장)[^22].

### 6-1. 데이터 모델 (PostgreSQL 예시, 제안)

```sql
-- 사용자
CREATE TABLE users (
  id            BIGSERIAL PRIMARY KEY,
  email         TEXT UNIQUE,
  nickname      TEXT,
  birth_year    INT,                       -- 만 14세 확인용(법정대리인 동의, 7장)
  marketing_opt_in BOOLEAN NOT NULL DEFAULT false,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  deleted_at    TIMESTAMPTZ                -- 탈퇴 시 파기 스케줄
);

-- 명식 입력(사용자 1명이 본인·가족·연인 등 여러 명식 보유)
CREATE TABLE birth_profiles (
  id            BIGSERIAL PRIMARY KEY,
  user_id       BIGINT REFERENCES users(id),
  label         TEXT,                      -- '나', '배우자' 등
  gender        CHAR(1) CHECK (gender IN ('M','F')),
  calendar_type TEXT CHECK (calendar_type IN ('solar','lunar')),
  is_leap_month BOOLEAN DEFAULT false,
  birth_date    DATE NOT NULL,             -- 입력한 그대로(음력이면 음력 날짜)
  birth_time    TIME,                      -- NULL = 시간 모름
  birth_tz      TEXT NOT NULL DEFAULT 'Asia/Seoul',
  birth_lon     NUMERIC(7,4),              -- 경도
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 계산 결과(엔진·정책 버전별 스냅샷)
CREATE TABLE charts (
  id              BIGSERIAL PRIMARY KEY,
  profile_id      BIGINT REFERENCES birth_profiles(id),
  engine_version  TEXT NOT NULL,           -- 예: 'lunar-js@1.7.7+krfix@3'
  time_policy     TEXT NOT NULL,           -- 'standard' | 'lmt' | 'true_solar'
  zi_policy       TEXT NOT NULL,           -- 'yajasi' | 'jojasi'
  utc_instant     TIMESTAMPTZ,             -- 보정 후 출생 순간
  correction_min  INT,                     -- 적용한 보정량(분)
  pillars         JSONB NOT NULL,          -- {year:"庚午", month:"辛巳", day:"...", hour:"..."}
  analysis        JSONB NOT NULL,          -- 오행·십신·지장간·대운 등 근거 JSON
  canonical_hash  TEXT NOT NULL,           -- 정규화 JSON 해시
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (profile_id, engine_version, time_policy, zi_policy)
);

-- 리포트(무료/유료, 생성 결과 영구 저장)
CREATE TABLE reports (
  id              BIGSERIAL PRIMARY KEY,
  chart_id        BIGINT REFERENCES charts(id),
  partner_chart_id BIGINT REFERENCES charts(id),  -- 궁합용
  report_type     TEXT NOT NULL,           -- 'free_summary','lifetime','yearly_2027','compat'
  rule_version    TEXT NOT NULL,
  prompt_version  TEXT,
  model_id        TEXT,                    -- 템플릿이면 NULL
  cache_key       TEXT UNIQUE NOT NULL,
  content         JSONB NOT NULL,          -- 섹션별 본문 + 근거규칙ID
  status          TEXT NOT NULL DEFAULT 'ready',
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 주문·결제(전자상거래법 기록 보존 고려)
CREATE TABLE orders (
  id            BIGSERIAL PRIMARY KEY,
  user_id       BIGINT REFERENCES users(id),
  product_code  TEXT NOT NULL,
  amount_krw    INT NOT NULL,
  report_id     BIGINT REFERENCES reports(id),
  status        TEXT NOT NULL,             -- 'paid','delivered','refunded'
  delivered_at  TIMESTAMPTZ,               -- 디지털콘텐츠 '제공 개시' 시점 기록(7장)
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 동의 이력(항목별·버전별)
CREATE TABLE consents (
  id          BIGSERIAL PRIMARY KEY,
  user_id     BIGINT REFERENCES users(id),
  kind        TEXT NOT NULL,   -- 'privacy_required','overseas_transfer','marketing','face_photo'
  doc_version TEXT NOT NULL,
  agreed      BOOLEAN NOT NULL,
  agreed_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

추가 테이블(6개월 차): `consultants`, `consult_sessions`, `posts`, `comments`, `daily_fortunes(date, zodiac, content, cache_key)`.

### 6-2. 아키텍처 예시 (제안)

```
[브라우저/앱]
    │  SSR·SSG 페이지(SEO) + 입력 폼
[웹 프론트: Next.js 등 SSR 프레임워크]
    │
[API 서버] ──── [계산 엔진 모듈]  (순수 함수, 버전 고정, 단위·회귀 테스트)
    │              ├─ CalendarEngine (lunar-js | tyme4ts | manseryeok 교체 가능)
    │              ├─ TimeCorrection (IANA tz + 경도 + 균시차)
    │              └─ RuleEngine → 근거 JSON
    │
    ├── [PostgreSQL] users / birth_profiles / charts / reports / orders / consents
    ├── [Redis 등 캐시] 오늘의 운세·띠별 운세, 세션
    ├── [작업 큐 워커] LLM 리포트 생성 → 검증기 → reports 저장 → PDF 렌더
    │        └── Claude API (근거 JSON만 전송)
    ├── [배치(cron)] 매일 띠별·일진 운세 사전 생성(Batches API), 절기표 연간 검증(KASI)
    └── [PG(결제대행)] 결제·환불 웹훅
```

- 계산 엔진은 **서버에서만 실행하는 순수 함수**로 두고, 같은 입력과 같은 버전이면 항상 같은 결과를 내게 합니다.
- 무료 만세력은 클라이언트(JS)에서 계산해도 되지만, **유료 리포트의 기준 결과는 반드시 서버 버전으로 고정**합니다.

### 7-1. 개인정보 (「개인정보 보호법」, 2026-09-08 공포·2027-03-09 시행 버전 기준[^22])

- [ ] **수집·이용 근거와 고지**: 동의를 받을 때는 목적, 항목, 보유기간, 거부권과 불이익을 알려야 합니다(제15조 제2항)[^22]. 생년월일시·성별·출생지를 '필수'로 둘지 최소화해서 판단하세요. 무료 계산은 저장하지 않는 방식(세션 안에서만 계산)도 검토하세요.
- [ ] **만 14세 미만**: 동의가 필요하면 법정대리인 동의를 받고 확인해야 합니다(제22조의2)[^22]. 가입할 때 연령을 확인하세요.
- [ ] **개인정보 처리방침 공개**(제30조)[^22].
- [ ] **국외 이전**: 해외 클라우드나 해외 LLM API로 개인정보를 보내면 제28조의8의 요건(별도 동의, 또는 처리방침 공개·개별 통지 등)이 적용됩니다. 별도 동의를 받을 때는 이전 항목, 국가, 시기·방법, 받는 자, 목적·보유기간, 거부 방법을 미리 알려야 합니다[^22]. → **LLM에는 간지·근거 JSON만 보내** 개인 식별성을 낮추는 설계를 권합니다(그래도 해당 여부는 전문가 확인 필요).
- [ ] **관상(얼굴 사진) 기능**: 「개인정보 보호법 시행령」 제18조 제3호는 "개인의 신체적, 생리적, 행동적 특징에 관한 정보로서 특정 개인을 알아볼 목적으로 일정한 기술적 수단을 통해 생성한 정보"를 민감정보로 정합니다[^23]. 민감정보는 별도 동의 등이 필요합니다(법 제23조)[^22]. 얼굴 특징값을 만들거나 저장하는 설계라면 별도 동의와 즉시 파기를 기본으로 하세요.
- [ ] **제3자 제공 고지**: 운세 콘텐츠를 외부 제휴사가 생성한다면 NHN '운수도원 투데이'처럼 제휴사 전달 사실을 알려야 합니다(사례)[^24].

### 7-2. 전자상거래 (「전자상거래 등에서의 소비자보호에 관한 법률」, 2026-01-20 공포·2026-07-21 시행 버전 기준[^25])

- [ ] **통신판매업 신고**: 공정거래위원회 또는 시·군·구청장에게 상호, 주소, 전화번호, 전자우편, 도메인, 호스트서버 소재지 등을 신고해야 합니다. 거래횟수·규모가 공정위 고시 기준 이하면 예외입니다(제12조 제1항)[^25]. 고시의 구체적 기준 수치는 이번에 확인하지 못했습니다(미확인).
- [ ] **사업자 정보 표시**: 상호·대표자, 주소·전화·이메일, 신고번호와 신고기관(제13조 제1항)[^25]. 사이트 하단 푸터에 표시하세요.
- [ ] **청약철회(환불) 7일 원칙**과 **디지털콘텐츠 예외**: 소비자는 원칙적으로 7일 이내에 청약을 철회할 수 있습니다(제17조 제1항). 다만 **디지털콘텐츠의 제공이 개시된 경우**에는 철회가 제한됩니다(제17조 제2항 제5호). 이 예외를 쓰려면 ① 철회가 불가능하다는 사실을 표시하고 ② **시험 사용 상품 등**을 제공해야 하며, 그렇게 하지 않으면 철회할 수 있습니다(제17조 제2항 단서·제6항)[^25].
  - 시험 사용 제공 방법: 미리보기(일부 이용), 한시적 이용, 체험용 콘텐츠, 또는 이것이 곤란하면 콘텐츠 정보 제공(시행령 제21조의2)[^26]. → **무료 요약 리포트와 목차·샘플 미리보기**를 이 요건에 맞춰 설계하세요.
  - 표시·광고나 계약 내용과 다르면 공급받은 날부터 3개월 이내, 그 사실을 안 날부터 30일 이내에 철회할 수 있습니다(제17조 제3항)[^25]. 리포트 품질(오류) 대응 절차를 마련하세요.
  - 디지털콘텐츠는 철회한 날부터 3영업일 이내 환급(제18조 제2항)[^25].
  - **분할 가능한 콘텐츠**(예: 12개월 월별 리포트)는 제공이 시작되지 않은 부분은 철회할 수 있습니다(제17조 제2항 제5호 단서)[^25]. 구독 상품 설계에 반영하세요.
- [ ] **다크패턴 금지**(제21조의2): 첫 화면에 총금액 일부만 표시, 미리 체크된 유료 옵션, 해지 절차를 가입보다 복잡하게 만들기, 반복 팝업 등이 금지됩니다[^25]. 구독 해지 버튼은 가입만큼 쉽게 만드세요.
- [ ] **환불 정책 문서화**: 위 내용을 반영한 이용약관·환불 규정을 결제 직전에 고지합니다.

### 7-3. 면책·표시 (법령 직접 근거 확인 안 함, 운영 권고)

- [ ] "본 서비스는 전통 명리학 이론에 기반한 오락·참고용 콘텐츠이며, 의료·법률·투자 등 전문적 판단을 대신하지 않습니다" 같은 면책 문구를 넣으세요.
- [ ] '적중률 ○○%', '100% 정확' 같은 근거 없는 광고 문구는 피하세요(표시·광고 관련 법령은 이번에 원문을 확인하지 않음, 미확인).
- [ ] AI가 생성한 문장이라는 사실을 표시하세요(이용자 신뢰 차원).

### 8-1. 경쟁사 가격대

- **(미확인)** 이번 조사에서는 점신·포스텔러·헬로우봇·천명 등의 **현재 유료 상품 가격을 확인하지 못했습니다**(앱스토어·웹 페이지 접속 불가, 검색 한도 소진).
- 가격 조사 방법(제안): ① 각 앱을 설치해 상품 목록 화면을 캡처(날짜 기록) ② App Store '앱 내 구입' 항목 확인 ③ 상담 플랫폼은 분당 단가와 최소 결제 금액을 기록 ④ 분기마다 갱신.
- 가격 설계(제안): 무료 요약 → 1만 원 안팎의 단품 리포트 → 상위 묶음 상품 → 상담의 사다리 구조. 실제 가격은 위 조사 결과를 보고 정하세요.

## 9. SEO·유튜브 연계 마케팅 (제안)

### 9-1. SEO

1. **프로그래매틱 SEO 페이지** (얇은 콘텐츠가 되지 않도록 페이지마다 고유 설명을 넣을 것)
   - 60갑자 일주 페이지(`/iljoo/gapja` 등): 일주 성향, 대표 특징, 같은 일주 Q&A
   - 띠별 오늘·이번 주·이번 달 운세(12띠 × 날짜)
   - 띠 궁합(12 × 12) 페이지, 일간 궁합(10 × 10) 페이지
   - 연도별 24절기 시각표(한국 시각 기준, 매년 갱신) → '입춘 시간' 같은 시즌 검색 수요
   - 만세력 날짜 페이지(오늘의 일진)
2. **시즌 캘린더**: 신년운세(11~1월 사전 노출), 입춘(2월 초), 수능·취업·이사철.
3. **기술 SEO**: SSR/SSG, 구조화 데이터(FAQ, Article), 사이트맵, 빠른 LCP. 네이버 검색 노출을 위해 네이버 서치어드바이저 등록과 사이트맵 제출(URL·절차는 이번에 확인하지 않음, 미확인).
4. **공유 루프**: 결과 카드 이미지(OG 이미지 자동 생성) → 카카오톡·인스타 공유 → 유입. MZ세대는 운세를 '재미·자기이해'로 소비하고 공유한다는 조사가 있습니다(12번 문서 5-3 참조)[^27].

### 9-2. 유튜브 연계

| 유튜브 콘텐츠 | 사이트 연결 |
|---|---|
| 일주별 성격 시리즈(60편) | 설명란과 고정 댓글 → 해당 일주 SEO 페이지 → 무료 만세력 |
| 띠별 주간 운세 쇼츠 | 사이트의 '내 띠 오늘 운세' |
| 입문 강의(천간·지지·오행·십신) | 사이트 '셀프 만세력 + 용어 사전' |
| 시청자 사연 풀이(익명·동의) | 상담 예약 |
| 신년운세 라이브 | 신년 리포트 사전 예약 |

- 채널과 사이트의 오행 색상 체계, 용어, 캐릭터를 통일합니다.
- 영상의 '근거 화면'(명식표)을 사이트 계산 결과 화면과 똑같이 만들어 신뢰를 쌓습니다.
- 유튜브 무료 강의 → 유료 멤버십 구조는 국내 명리 강의 채널에서도 쓰입니다(12번 문서 1-1)[^27].
